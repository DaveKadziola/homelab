# Security

Operating model. Dated findings: [`security-audit-2026-09-10.md`](security-audit-2026-09-10.md).

## Identities

One real mailbox per environment (Proton):

| Env | Mailbox |
|-----|---------|
| dev | `dev-homelabnotifications@pm.me` |
| prod | `prod-homelabnotifications@pm.me` |

Apps that login by **email** use that mailbox. Apps that login by **username** use `admin`. Never use `*.local` as an email — pgAdmin refuses reserved TLDs.

Generator: `utils/gen-app-credentials.sh` → GH Environment secret + Bitwarden staging file + `~/.homelab-secrets/<env>/<NAME>`. Values never go in git. Argon2/bcrypt **hashes** may.

`BESZEL_KEY` is issued by the hub at bootstrap (`issued_by: beszel`), not generated by the script.

## Auth coverage

| Layer | Today |
|-------|--------|
| Authelia | Deployed (profile `auth`). Cookie domain `homelab.local`. Not yet in front of every app. |
| App admins | Converged by `utils/bootstrap/*.sh` where the app has an API/CLI |
| SSH | Key-only to the apps guest |
| TLS | Authelia self-signed on `:9091`. Public grocery ACME is a prod HAProxy job. |

## Known sharp edges (will be in F9)

- Postgres `:5432` published on the apps host
- Docker socket mounted into Portainer and Dozzle
- Most images are `:latest`
- Homarr CLI hung and once leaked a password on the host `ps` line — **rotated**. Never pass Homarr’s password on `docker exec` argv.

## Rotate a login

```bash
./utils/gen-app-credentials.sh --env dev --secret PORTAINER_ADMIN_PASSWORD --rotate
# copy lands in ~/.homelab-secrets/dev/ and GH env `dev`
./utils/bootstrap/portainer.sh --env dev --host 192.168.122.50
```

Legacy one-file caches (`~/.homelab-portainer-dev-pass`, …) are stale. Use `~/.homelab-secrets/<env>/`.

## Bitwarden (mandatory copy)

GH cannot read secrets back. After generate, sync the laptop cache:

```bash
# CLI lives in ~/.local/bin/bw (official 2025.9.0)
export PATH="$HOME/.local/bin:$PATH"
bw login          # email + master password + 2FA — interactive
export BW_SESSION="$(bw unlock --raw)"
./utils/sync-cache-to-bitwarden.sh --env all
bw lock
unset BW_SESSION
```

Notes are named `homelab/<NAME>/<env>` in folder `homelab`. The script never prints values.

Still GH-only (not in the cache): `POSTGRES_PASSWORD` (both envs — F1, write-only), prod `UBUNTU_DOCKER_*` / Proxmox placeholders. Those need a value you already stored, or `--regenerate` (changes the live secret).

Operator sync: **2026-09-11** (`--env all`). Vault is locked on this laptop; no session is kept in the repo or chat.

Staging `.txt` files under `~/homelab-bitwarden-*` are leftovers — shred after you are happy with the vault:

```bash
shred -u ~/homelab-bitwarden-*.txt
```

## rclone / pCloud (prod offsite)

```bash
rclone config create pcloud pcloud    # browser OAuth, one time
./utils/setup-rclone-pcloud.sh --push-gh
./utils/sync-cache-to-bitwarden.sh --env prod   # picks up ~/.homelab-secrets/prod/RCLONE_CONFIG
```

DEV does not push offsite (`storage.yml` `rclone: false`).
